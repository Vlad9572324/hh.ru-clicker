# Mobile Migration Guide — переход с web-flow на mobile OTP

Гайд для пользователей бота: как переключить существующий аккаунт hh.ru
с браузерных cookies (web-flow) на авторизацию через SMS-код (mobile OTP)
и что при этом изменится.

Все названия вкладок и кнопок ниже — ровно те, что есть в дашборде
(`static/index.html`, `static/js/app.js`).

---

## 1. Что такое mobile-режим и зачем он

У бота теперь **два канала** общения с hh.ru:

| Канал | Что использует | Как получается доступ |
|---|---|---|
| **web-flow** (старый) | cookies браузера (`hhtoken`, `_xsrf`, …) + web-страницы hh.ru / `chatik.hh.ru` | Copy as cURL из браузера |
| **mobile OTP** (новый) | OAuth Bearer-токен мобильного приложения HH (`api.hh.ru`) | SMS-код / письмо (штатный OTP-поток Android-приложения HH) |

Mobile-режим — это штатный двухэтапный OTP-поток Android-клиента HH
(HTTP-контракт зеркалит декомпилированный HH Android 26.29,
`app/mobile_auth.py`): бот запрашивает одноразовый код, вы вводите его,
HH выдаёт `access_token` + `refresh_token` официального OAuth.

**Зачем переходить:**

- **Стабильнее** — OAuth-токен живёт сам по себе и автоматически
  продлевается (`refresh_token`), не слетает от DDoS-Guard, глючных
  cookie-ротаций и «протухших» браузерных сессий.
- **Нативный API** — отклики идут через официальный
  `POST api.hh.ru/negotiations`: «без капчи, чистый JSON»
  (формулировка из UI дашборда).
- **Автопродление** — фоновый worker каждые 6 часов обновляет токены,
  у которых осталось < 48 часов (`app/manager.py::_oauth_refresh_worker`).
- После OTP-входа бот **сам** создаёт/обновляет и браузерную сессию
  через штатный Android autologin-мост (`GET /autologin_key/{hhid}` →
  одноразовый `loginkey` → cookies `hhtoken`/`hhuid`/`_xsrf`), так что
  web-канал остаётся запасным.

**Когда mobile НЕвозможен:**

- К аккаунту **не привязан ни телефон, ни email** — HH некуда слать код.
- HH потребовал **CAPTCHA** при запросе кода, а пройти её не получается.
- На аккаунте **нет резюме** — бот привязывает токены к `resume_hash`,
  а отклики без резюме невозможны в любом режиме.
- Нужен вход в **новый** аккаунт: OTP-поток работает с
  `allow_multiaccount_creation=false` — только вход в существующий
  аккаунт, не регистрация.

## 2. Prerequisites

До начала убедитесь, что у вас есть:

1. **Аккаунт hh.ru с привязанным телефоном** (для входа по SMS)
   или email (для входа по письму).
2. **Хотя бы одно резюме** на аккаунте.
3. **Запущенный дашборд бота** (`http://localhost:8000` или ваш адрес).
4. Если хотите переключить **существующую** сессию, а не создавать новую —
   она должна уже быть в дашборде (Настройки → 🌐 Браузерные сессии):
   сопоставление идёт по `resume_hash` резюме.

Браузерные cookies для самого OTP-входа **не нужны** — поток полностью
самостоятельный.

## 3. Пошаговая инструкция

Все действия — во вкладке **⚙️ Настройки**, группа **🔌 Подключение**,
секция **📱 Авторизация по телефону / email** (секция стоит между
«🌐 Прокси и исходящий IP» и «🌐 Браузерные сессии»).

```
⚙️ Настройки
└── 🔌 Подключение
    ├── 🌐 Прокси и исходящий IP
    ├── 📱 Авторизация по телефону / email   ← сюда
    │     [Email] [Телефон]                  ← переключатель типа входа
    │     [ +79991234567        ] [Отправить код]  Повтор через N с
    │     ── после отправки кода появляется строка ввода: ──
    │     [Код из SMS / письма ] [Подтвердить] [Отправить повторно] [Выйти / сбросить]
    │     (статус) Код отправлен: +***4567
    │     └── ⚙️ Расширенные параметры мобильного клиента  (свёрнуто, см. шаг 6)
    └── 🌐 Браузерные сессии
```

**Шаг 1. Выберите тип входа.** Нажмите кнопку **Телефон** (или **Email**,
если хотите получить код письмом). Поле ввода поменяет placeholder:
для телефона `+79991234567`, для email `name@example.com`.

**Шаг 2. Отправьте код.** Введите телефон, привязанный к аккаунту hh.ru,
и нажмите **Отправить код**. Код уходит **только по нажатию кнопки**.
Статус покажет `Код отправлен: +***4567` (логин маскируется), рядом
появится таймер `Повтор через N с` — до него кнопку отправить повторно
нельзя.

**Шаг 3. Введите код.** Когда придёт SMS (или письмо), введите цифры
в поле **Код из SMS / письма** и нажмите **Подтвердить**. Длина кода
проверяется: HH сообщает её в ответе на запрос кода, и бот не примет
код другой длины.

**Шаг 4. Дождитесь завершения.** Статус сменится на
`Проверка кода и загрузка данных…`. Это может занять **до нескольких
минут**: бот последовательно делает вход, запрашивает `/me` и
`resumes/mine`, сохраняет токены, собирает похожие вакансии и проходит
autologin-мост за браузерными cookies. Успех выглядит так:

```
✅ Авторизация успешна: Имя Фамилия
Резюме: 2; вакансии: 37. Обновлено браузерных сессий: 2.
```

**Шаг 5. Запустите бота.** OTP-вход создаёт/обновляет сессию с
`bot_active=false` — сам бот не стартует. Перейдите на **📊 Главная**
(или Настройки → 🌐 Браузерные сессии) и нажмите **▶ Запустить** на
карточке сессии.

**Шаг 6 (опционально). Расширенные параметры.** Внутри секции есть
сворачиваемый блок **⚙️ Расширенные параметры мобильного клиента**:
пакет и версия приложения (`APP_PACKAGE`, `APP_VERSION_NAME`,
`APP_VERSION_CODE`), модель устройства, Android release, `Device UUID`,
шаблон User-Agent, client credentials. Кнопки: **💾 Сохранить настройки**,
**✓ Проверить настройки**, **↻ Новый UUID**,
**Восстановить значения по умолчанию**. Рядом с каждым полем виден
источник значения; приоритет: `web → environment → file → default`
(env-переменные `HH_APP_PACKAGE`, `HH_DEVICE_MODEL`, `HH_DEVICE_UUID`
и т.д.). **Обычному пользователю ничего менять не нужно** — значения по
умолчанию соответствуют штатному Android-клиенту HH.

### Что доступно из API (без UI)

OTP-флоу обслуживают эндпоинты роутера `/api/mobile-auth`
(`app/routes/mobile_auth.py`):

| Эндпоинт | Действие |
|---|---|
| `POST /api/mobile-auth/request-code` | отправить код (`login`, `login_type: phone\|email`) |
| `POST /api/mobile-auth/verify` | подтвердить код, сделать вход |
| `GET  /api/mobile-auth/status` | стадия (`idle` / `code_requested`) |
| `POST /api/mobile-auth/logout` | сбросить состояние и удалить mobile-токены |
| `GET/PUT /api/mobile-auth/settings` | параметры мобильного клиента |
| `POST /api/mobile-auth/settings/validate` | проверка параметров без запроса к HH |
| `POST /api/mobile-auth/settings/reset` | сброс к значениям по умолчанию |
| `POST /api/mobile-auth/settings/uuid` | сгенерировать новый Device UUID |

## 4. Что происходит при переключении

**Сохраняется (не трогаем):**

- все настройки бота (фильтры, пул URL, LLM-профили, лимиты);
- история откликов / интервью / тестов;
- старые сессии других аккаунтов.

**Меняется:**

- **Токены**: для каждого найденного резюме в `data/oauth_tokens.json`
  записывается пара `access_token` + `refresh_token` с меткой
  `source: "mobile_otp"` (атомарно, файл 0600). `access_token` живёт
  ~14 дней и продлевается автоматически.
- **Браузерные сессии**: в `data/browser_sessions.json` для каждого
  резюме — либо **обновляется** существующая сессия с тем же
  `resume_hash` (cookies заменяются на полученные через autologin,
  включается `use_oauth: true`), либо **создаётся новая** (имя —
  «Имя Фамилия» или «HH Mobile», цвет cyan).
- **Поведение откликов**: сессия стартует с `use_oauth: true`, т.е.
  отклики идут через официальный OAuth API (`POST api.hh.ru/negotiations`)
  — без капчи, но **по одному запросу за раз, без пакетов**. На карточке
  аккаунта это видно по зелёной кнопке **🔑API** (а не **🌐Web**).
- **Чаты**: отправка сообщений сначала пробует OAuth-канал
  (`api.hh.ru/common/chats/.../messages`), fallback на `chatik.hh.ru`.
- **Ошибки авторизации**: ответ `403` при отклике больше **не** считается
  «протухшим токеном» (это бизнес-отказ HH: опросник, ограничения
  вакансии) — токены не затираются; только `401` инвалидирует токен
  и запускает перевыпуск через `refresh_token`.
- Если HH не отдал обязательные cookies при autologin — OAuth остаётся
  рабочим, но браузерная сессия не создаётся; статус покажет
  `OAuth работает, но браузерная сессия не создана: <причина>`.

## 5. Как переключить обратно на web

Мягкий вариант (cookies, полученные через autologin — это обычные
валидные web-cookies, их не нужно ниоткуда доставать заново):

1. На карточке аккаунта (**📊 Главная**) нажмите кнопку **🔑API** —
   она переключится на **🌐Web** («Метод откликов: OAuth API или
   Web cookies»). Отклики снова пойдут через cookies.

Полный откат (убрать mobile-артефакты):

2. В секции **📱 Авторизация по телефону / email** нажмите
   **Выйти / сбросить** — удалятся локальное OTP-состояние и все токены
   с `source: mobile_otp` (cookies и сами сессии при этом **не**
   удаляются).
3. Если сессия больше не нужна — **✕ Удалить** на её карточке, и при
   необходимости добавьте свою браузерную: Настройки → 🌐 Браузерные
   сессии → **➕ Добавить сессию из браузера** (cURL из F12).
4. Либо точечно через JSON-редактор настроек: поле `"mode": "web"`
   у аккаунта/сессии (см. раздел 6).

## 6. Поля `mode` и `default_client_mode`

Каждый аккаунт в `data/accounts.json` и каждая сессия в
`data/browser_sessions.json` принимает **опциональное** поле `mode`
со значениями:

| Значение | Смысл |
|---|---|
| `"web"` | всегда web-клиент (cookies hh.ru) |
| `"mobile"` | всегда mobile-клиент (OAuth Bearer api.hh.ru) |
| `"auto"` | mobile, если для `resume_hash` есть живой OAuth-токен, иначе web |

Если поля нет — действует глобальная настройка `default_client_mode`
в `data/config.json` (по умолчанию `"auto"`; правится через JSON-editor
или `set_config`). Неизвестное значение трактуется как `"web"`.
Выбор делает `app/hh_client_factory.py::get_client(account)`.

Нюанс для понимающих: это поле введено в **Phase 0** рефакторинга
(`app/hh_client*.py`). Абстракция `HHClient` уже готова, но бот
переводится на неё постепенно — сейчас фактический канал определяется
тумблером **🔑API/🌐Web** на карточке, `use_oauth_apply` в настройках
и наличием токена. Поле `mode` можно заполнять уже сейчас, оно
сохраняется на диск и подхватится следующими фазами.

## 7. Известные ограничения

1. **Нужен привязанный телефон или email.** HH отправляет SMS
   (или письмо) — без привязанного контакта пройти OTP невозможно.
   В этом случае оставайтесь на web-flow: он продолжает работать как
   раньше.
2. **CAPTCHA.** HH может потребовать капчу при запросе кода. В статусе
   появится жёлтая ссылка **🧩 Пройти CAPTCHA** — откройте её в браузере,
   пройдите проверку и повторите запрос кода. Ссылки принимаются только
   с `hh.ru` / `*.hh.ru`.
3. **Rate-limit и срок жизни кода.** Слишком частые запросы дают
   «Слишком много запросов. Повторите позже.» (429); протухший код —
   «Код подтверждения истёк. Запросите новый код.». Неверный код —
   «Неверный код подтверждения.», можно ввести заново.
4. **Требует работающего бота для автопродления.** `refresh_token`
   живёт ~14 дней; фоновый worker продлевает токены только пока бот
   запущен. Бот остановлен дольше ~2 недель → придётся пройти OTP заново.
5. **OAuth-отклики не пакетные**: один запрос за раз (медленнее
   web-батчей) — это ограничение официального API.
6. **Опросники и тесты — только web-канал.** В OAuth/degraded-режиме
   бот откликается «без опросников/тестов» (подпись чекбокса
   «🔑 OAuth-fallback при протухших cookies»). Для вакансий с анкетами
   нужны живые cookies.
7. **Mobile-клиент покрывает не все операции (Phase 0).** В
   `MobileHHClient` реально работают `fetch_counters()` и
   OAuth-extras (сохранённые поиски, избранное, чёрный список, статус
   резюме, статистика); переговоры/чаты (phase 2), отклики (phase 3)
   и резюме/статистика (phase 4) пока кидают `NotImplementedError`.
   Поэтому «чистый» mobile-режим без web-запасника в следующих фазах
   включайте осторожно; переключённые через OTP сессии всегда оставляют
   cookies как fallback.
8. **Только вход, не регистрация**: `allow_multiaccount_creation=false` —
   новый аккаунт через OTP создать нельзя.

## 8. FAQ

**Q: Токен протух (`expires_hours` → 0 на бейдже). Что делать?**
A: Ничего. Бот продлевает токены сам: лениво — при первом запросе,
и фоново — каждые 6 часов для токенов с остатком < 48 часов. Вручную
перевыпускать нужно только если бот долго стоял и `refresh_token` тоже
умер (~14 дней) — тогда просто пройдите OTP заново в той же секции
**📱 Авторизация по телефону / email**.

**Q: Отлик вернул 401 — бот сломался?**
A: Нет. `401` означает только «плохой токен»: бот инвалидирует его и
тут же получает новый по `refresh_token`. Если одновременно протухли
и cookies, а на аккаунте включён чекбокс «🔑 OAuth-fallback при
протухших cookies» (или `use_oauth`) — бот перейдёт в degraded-режим
через OAuth API и напишет в лог «⚠️ Web cookies истекли → переключаюсь
на OAuth API». Обратите внимание: `403` — это **не** ошибка авторизации,
а бизнес-отказ HH (опросник, ограничения вакансии); токены при 403
не затираются.

**Q: Как убедиться, что аккаунт реально работает через mobile?**
A: Смотрите бейдж на карточке аккаунта:
`🍪 Куки ✅ | 🔑 OAuth: ✅ токен (Nч)` — обе части зелёные, и кнопка
метода откликов показывает **🔑API**. Если
`🔑 OAuth: ⏳ будет получен при отклике` — токена ещё нет, он появится
после первого OAuth-запроса (для mobile-сессий он уже сохранён при входе).

**Q: Что делает «Выйти / сбросить»?**
A: Очищает локальное состояние OTP (`data/mobile_auth_state.json`) и
удаляет из `data/oauth_tokens.json` **только** токены с
`source: mobile_otp`. Браузерные сессии и cookies не удаляются;
статус вернётся к `idle`.

**Q: Я переключился, а бот всё равно откликается через web. Почему?**
A: Проверьте по порядку: (1) кнопка на карточке аккаунта должна
показывать **🔑API**, а не **🌐Web**; (2) бейдж должен показывать
`🔑 OAuth: ✅ токен`; (3) в Настройки → 🏢 Фильтры и автоматизация →
подраздел **🔑 Метод откликов** есть глобальный чекбокс «OAuth API
(через токен Android-приложения — без капчи, чистый JSON)» — он
включает OAuth-отклики для всех аккаунтов сразу.

## AI-помощник Хэдди

В дашборде доступна вкладка **«🤖 HH Хэдди»** для общения со встроенным
HH.ru AI-помощником по поиску вакансий. Функция работает только для аккаунтов
с `mode: mobile`, поскольку использует OAuth и mobile API. При первом открытии
создаётся (или возобновляется) персональный чат аккаунта; история обновляется
автоматически раз в 30 секунд и вручную кнопкой в интерфейсе.

API дашборда: `GET /api/account/{idx}/hedi/start`,
`GET /api/account/{idx}/hedi/history?limit=50` и
`POST /api/account/{idx}/hedi/send` с JSON `{"text": "..."}`.
