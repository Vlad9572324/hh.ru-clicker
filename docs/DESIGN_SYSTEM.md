# Дизайн-система интерфейса

## Статус и стек

Интерфейс — **vanilla HTML + JavaScript без build-step**, визуальная библиотека —
**Tabler 1.5.1** (локально закреплённая копия). Не подключайте Bootstrap отдельно:
Tabler уже основан на нём и предоставляет его классы.

| Файл | Ответственность |
|---|---|
| `static/vendor/tabler/tabler.min.css` / `.js` | Вендорские assets Tabler. Не редактировать вручную. |
| `static/css/tabler-adapter.css` | Единственный базовый stylesheet панели: layout, токены, совместимость классов бота и dark mode. |
| `static/js/tabler-upgrade.js` | Постепенно назначает Tabler-классы static и динамически добавленным DOM-элементам. |
| `static/index.html` | Семантический каркас и подключение assets. |
| `static/js/app.js` | Данные, события и HTML динамических карточек. Новый HTML должен сразу иметь Tabler-классы, а не полагаться только на adapter. |
| `static/css/features/*.css` | Изолированный стиль конкретной фичи; только токены и scoped-селекторы фичи. |

`static/css/style.css` и `static/css/theme-autoclicker.css` являются legacy-файлами
и **не подключаются**. Не возвращайте их в `index.html`.

## Обязательные компоненты

| Задача | Использовать |
|---|---|
| Верхняя панель | `navbar`, `navbar-expand-md`, `sticky-top` |
| Переключение экранов | `nav nav-tabs` и `nav-link` |
| Контейнер данных/настроек | `card`, при необходимости `card-header`, `card-body`, `card-footer` |
| Основное действие | `btn btn-primary` |
| Нейтральное действие | `btn btn-outline-secondary` |
| Рискованное или удаление | `btn btn-outline-danger` или `btn btn-danger` после подтверждения |
| Маленькая кнопка в строке | добавить `btn-sm` |
| Текстовое поле/textarea | `form-control` + связанный `<label>` |
| Обычный select | `form-select` + связанный `<label>` |
| Checkbox/switch | `form-check` или `form-check form-switch` |
| Статус/счётчик | `badge` с семантическим цветом (`bg-primary-lt`, `bg-success-lt`, `bg-warning-lt`, `bg-danger-lt`) |
| Информационное/ошибка | `alert alert-info`, `alert alert-warning`, `alert alert-danger` |
| Таблица | `table table-vcenter table-hover`; контейнер — `table-responsive` |
| Раскрывающийся вторичный блок | нативный `details`/`summary`, оформленный как секция карточки |
| Подтверждение действия | Tabler/Bootstrap modal, а не самодельный overlay |
| Временный результат команды | toast или alert рядом с действием |
| Пустой список | единая карточка с `text-secondary`, понятной причиной и следующим действием |

## Темы и токены

- Тема хранится в `localStorage` под ключом `hh-dashboard-theme` и включается
  кнопкой `#theme-btn`.
- Используйте `data-bs-theme="light" | "dark"`; не делайте отдельные тёмные
  версии компонентов и не проверяйте тему в бизнес-логике.
- Цвета брать только из Tabler-токенов или алиасов в `tabler-adapter.css`:
  `var(--cyan)`, `var(--green)`, `var(--yellow)`, `var(--red)`, `var(--dim)`,
  `var(--text)`, `var(--bg-card)`.
- Цвет передаёт смысл: primary — действие/информация, success — успешно,
  warning — требуется внимание, danger — ошибка/необратимое действие. Не
  назначать случайные акцентные цвета ради декора.
- Иконки должны пояснять текст, а не заменять его. Для новых иконок предпочитать
  Tabler Icons; emoji оставлять только там, где они уже являются частью данных
  или перевода.

## Правила реализации

- Не добавлять `style="..."` в новый HTML и не создавать новый `style.cssText`
  для визуального оформления. Вместо этого добавьте семантический класс в
  `tabler-adapter.css` или scoped CSS фичи.
- Исключение: inline style допустим только для значения, вычисляемого во время
  выполнения и не имеющего конечного набора классов, например ширина progress
  bar. Состояние (`успех`, `ошибка`, `ожидание`) всегда выражается классом.
- Не добавлять CSS-фреймворки, CDN, React/Vue или build-step без отдельного
  решения владельца. Assets Tabler должны оставаться локальными.
- Не стилизовать по тексту, порядку DOM или глобальным селекторам наподобие
  `button { ... }`. Используйте класс компонента или контейнер фичи.
- Новая динамическая разметка в `app.js` сразу получает корректные Tabler-классы.
  `tabler-upgrade.js` — переходная совместимость, не замена качественной
  разметки.
- Не менять ID, `data-*` атрибуты, inline event handlers или ARIA-атрибуты без
  проверки связанной логики: они образуют контракт с `app.js` и feature scripts.
- Для интерактивных элементов сохранять видимый focus, доступную подпись и
  состояние `disabled`; для икон-кнопок обязательно `title` или `aria-label`.

## План очистки legacy-разметки

Каждый UI-PR должен выбирать законченную область, а не добавлять ещё один слой
стилей поверх неё:

1. Заменить inline styles в области на классы и компоненты из таблицы выше.
2. Перевести статический HTML и HTML, создаваемый через `app.js`, одновременно.
3. Удалить заменённые legacy-селекторы и не оставлять неиспользуемые классы.
4. Проверить светлую и тёмную темы, desktop и узкий viewport.
5. Проверить, что WebSocket snapshot не меняет внешний вид новой области обратно
   на legacy-версию.

Приоритетные области: карточка аккаунта и Smart Filters, страницы логов/таблиц,
настройки и формы авторизации, LLM/HH Hedi, затем feature-панели.

## Критерии готовности UI-изменения

```powershell
node --check static/js/app.js
node --check static/js/tabler-upgrade.js
pytest -q
```

Перед PR вручную проверьте:

- кнопку темы и сохранение выбора после reload;
- пустое и заполненное состояние изменённого экрана;
- кнопки, формы, disabled/error/success состояния;
- ширину 1440px и 375px;
- отсутствие новых inline-стилей и возвращённого legacy stylesheet.
